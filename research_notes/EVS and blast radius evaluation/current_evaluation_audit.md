## 1. What the paper and docs define as EVS and blast radius, and where it is implemented

### Takeaway
The paper defines blast radius BR_k (Algorithm 1, k = 1, direction by impact mode) and EVS = min(10, Env·(1+βP(u))), where Env is CVSS v3.1 Environmental with graph-derived CR/IR/AR, MAV, E. Crucially, **BR_1 never enters the EVS number**: the score uses P(u), a separate unbounded, outbound-only reachability sum. And **the paper has no evaluation section at all**, so "consistency with the paper" constrains only the method, not the evaluation design.

### Cited Findings
- The PDF's section headings are only "I. Introduction", "II. Related Work", "III. Our Proposed System" (System overview, CTI KG, CA KG, Affected Assets Identification, EVS, Threat Report), then References. There is no Evaluation/Experiments/Results/Conclusion section; the only promise is "We build it for a laboratory network so that asset values and attack scenarios are controlled during evaluation" — [paper PDF, text lines ~302-304](docs/Context_aware_vulnerability_classification_with_knowledge_graphs_and_security_intelligence.pdf)
- Paper contributions: KG representation, "Context-Aware Classification Model ... compute the environmental vulnerability score and classify the vulnerability", tool integration, LLM threat report — [paper, Introduction bullet list](docs/Context_aware_vulnerability_classification_with_knowledge_graphs_and_security_intelligence.pdf). The abstract says "The security requirements of the nodes within the affected zone are used to calculate the EVS" — i.e. the abstract implies the blast radius feeds the score.
- Blast radius (paper Eqs. 5–9): G_R = CONNECTS_TO edges (u,v) with π(u,v) (same zone or zone(u) ALLOWED_TO_REACH zone(v)); m(c) = compromise if CVSS C or I ≠ N, else disruption; compromise → out-neighbours N⁺(a), disruption → in-neighbours N⁻(a); BR_k(a,c) = {v : d_c(a,v) ≤ k}, includes a; "In this work, we set k = 1"; justification: "Assets beyond the first hop can only be reached if the attacker exploits further, independent weaknesses ... outside the scope"; cost O(deg(a)) — [paper §III.A.2, Algorithm 1](docs/Context_aware_vulnerability_classification_with_knowledge_graphs_and_security_intelligence.pdf)
- EVS (paper Eqs. 10–18): MISS = min(1−(1−CR·MC)(1−IR·MI)(1−AR·MA), 0.915); Env per CVSS v3.1 env equation with T = E·RL·RC; Table I: CR/IR/AR from Asset node, MAV = base AV if an ALLOWED_TO_REACH path connects Internet to zone(u), else AV:N lowered to A; E (Eq. 14) = H if α(c,u)=1 (alert reports c on u) or c ∈ KEV or SSVC s(c)=active; P if poc; U if none; X otherwise; RL, RC = Not Defined. crit(v) = max(CR_v,IR_v,AR_v) − 0.5 (Eq. 15); P(u) = 1/(|V_A|−1) Σ_{v∈R(u)\{u}} crit(v)·γ^{d(u,v)} (Eq. 16), R(u) = assets reachable through CONNECTS_TO with zone rule (no depth bound, direction not stated); EVS = min(10, Env·(1+βP(u))) (Eq. 17); level by CVSS qualitative scale (Eq. 18). "Each graph signal contributes to exactly one term" — [paper §III.A.3](docs/Context_aware_vulnerability_classification_with_knowledge_graphs_and_security_intelligence.pdf)
- Implementation: `score_kg/model.py` — `crit` (L19-21), `impact_mode` (L24-27), `reachability_edges` (L30-34), `blast_radius` = BFS to depth k, reversed for disruption (L60-62), `propagation` = `distances(edges, asset)` with **no reverse and no k** (L65-71), `evs` with CVSS roundup (L80-82); E rule in `score_kg/cvss31.py::exploit_maturity` (L38-56); Env via the `cvss` library (`cvss31.environmental`, L59-63) — [score_kg/model.py](score_kg/model.py), [score_kg/cvss31.py](score_kg/cvss31.py)
- Parameters: β = 0.5 (`SCORE_BETA`), γ = 0.5 (`SCORE_GAMMA`), k = 1 (`SCORE_BLAST_K`) — [score_kg/config.py L12-14](score_kg/config.py)
- docs/scoring.md restates these with equation numbers shifted by one versus the PDF (scoring.md calls crit Eq. 14, P Eq. 15, EVS Eq. 16, level Eq. 17; the PDF uses 15/16/17/18 and Eq. 14 for E) — [docs/scoring.md L56-62](docs/scoring.md). scoring.md §5 says E is "Deliberately broader than the paper's Table I, which has only 'H if the alert maps to c on u'" (L80), but the current PDF's Eq. 14 already includes KEV/SSVC — stale doc text.
- In this lab E_R = all 12 CONNECTS_TO edges (the zone predicate π removes none). Computed P(u) with β = γ = 0.5 on the 17-host lab: max is Jump 0.1211 (uplift ×1.0605), Jenkins 0.0859 (×1.043), Nginx 0.0547 (×1.027), Web 0.0469; 8 of 17 assets have P = 0 (PostgreSQL, Files-SMB, Dep-PC, DNS, HR-DB, Redis, Dev-PC, plus nothing outbound) — computed by me from [lab/asset_edges.csv](lab/asset_edges.csv), [lab/assets.csv](lab/assets.csv), [lab/zone_edges.csv](lab/zone_edges.csv) with `score_kg.model`.

### Inferences
- The "blast radius" contributes to the EVS only through P(u), and in this lab that term moves Env by at most +6 % (≤ ~0.6 points, usually 0–0.3 after roundup). Any ladder step L3→L4 can therefore barely change a ranking; a flat L4−L3 is expected by construction, not a finding.
- P(u) is per-asset and independent of c (always outbound, ignoring m(c)), so it cannot reorder CVEs on the same host and does not use the impact-mode direction that Algorithm 1 introduces. BR_1 (what Part B validates) and R(u) (what feeds EVS) are different objects. A reviewer can say: "Part B validates a set you don't use in the score."
- Because π never prunes an edge, the "zone constrains traversal" claim of Eqs. 5–6 is not exercised by the lab at all.

### Gaps
- The paper gives no evaluation protocol, hypotheses, or metrics; whatever Part A/B is, it currently has no counterpart text in the draft to stay consistent with (only the method).

## 2. What Part A (ladder) and Part B (variants) do

### Takeaway
Part A is a cumulative ablation ladder L0→L4 (CVSS base → +CR/IR/AR → +MAV → +E → +P = EVS) plus baselines (EPSS, KEV, SSVC, Wazuh rule.level, WazuhVD), ranked against pentest outcomes with NDCG/P@k/MRR and paired bootstrap. Three label sets: A1 (asset×CVE exploited yes/no), A2 (alert instances graded 0–3 within scenario windows), A3 (forward-in-time KEV). Part B compares blast-radius variants B0–B5 by set precision/recall/F1 against lab-measured network/usable/dependents sets, plus a downstream NDCG row.

## 4. Methodological weaknesses

### Takeaway
The main problems are (a) label scarcity: one positive in A1, zero in A3, A2 near-empty → zero statistical power; (b) circularity in both parts: KEV/SSVC feed E and are also baselines that "explain" the only positive; Part B ground truth is generated by configuration the same team wrote to match `asset_edges.csv`; (c) a mismatch between what Part B validates (BR_1) and what the EVS uses (unbounded P(u), ≤ 6 % effect); (d) metric choices that hand out free credit (empty sets, id tiebreaks, NDCG@10 on ≤ 9 items); (e) no test of the central claim that the *same CVE should get different priority on different assets*.

### Cited Findings
- **Single positive / ceiling effect** acknowledged: "A1 is still flat at NDCG@10 = 1.000 for every score, the ceiling effect described above, until sampled rows are labelled" — [docs/evaluation.md L243-244](docs/evaluation.md); evaluation.md L130-136.
- **Selection bias of A1**: all 9 labelled rows are hand-picked (0 sampled) — [data/reports/eval_score_ablation.md](data/reports/eval_score_ablation.md); the plan itself says "Today A1 rows are hand-picked, which is a selection bias a reviewer will raise" — [docs/PLAN.md §8 (diff)](docs/PLAN.md).
- **Weak negatives**: Prant's rows "no timestamped evidence file ... verify before reporting" — [evaluation/pentest_results.csv](evaluation/pentest_results.csv); "generic probes ... that do not exercise the vulnerable feature ... read them as weak negatives" — [docs/evaluation.md L161-163](docs/evaluation.md). Several other "no" rows are "not configured"/"no vulnerable rewrite config" (S09) — i.e. *not reachable* outcomes recorded as negatives, which is really an environmental-applicability label.
- **Sampled frame will mostly be not_tried**: "Only 3 of the 20 are a network service of the host; the rest are local library CVEs (libpcre2, binutils, perl, gnutls…). Expect many not_tried" — [docs/evaluation.md L236-238](docs/evaluation.md); candidates list confirms 17 of 20 have `service=False` — [evaluation/pentest_candidates.csv](evaluation/pentest_candidates.csv). Since `not_tried` is dropped (labels.py L169), the sampled design shrinks toward the same handful of service CVEs; dropping not_tried is also informative missingness (MNAR) that correlates with AV/feature reachability, which is exactly what MAV/L2 models.
- **Circularity: KEV/SSVC in E vs exploited label**: E = H if c ∈ KEV or SSVC active (cvss31.py L48-51); the one A1 positive is KEV (`KEV 1.0`, eval_score_ablation.csv). Prior author note: Prant's "KEV/AUC scripts are not used here because KEV feeds E and would make the comparison circular" — [docs/evaluation.md L164-165](docs/evaluation.md). KEV as a baseline and inside L3 means L3/L4 vs KEV is not separable on such data.
- **Circularity: SSVC baseline uses CR/IR/AR** via `ssvc.mission_prevalence(asset["cr"], asset["ir"], asset["ar"])` — [eval_kg/ladder.py L79](eval_kg/ladder.py); so the "SSVC" baseline is already partly environmental, not an independent context-free baseline.
- **Circularity: Part B ground truth vs model input**: `lab/asset_edges.csv` header: "the others are the intended application flows, each exercised by the source host's health check in lab_env/eval/checks.csv" — [lab/asset_edges.csv L1-3](lab/asset_edges.csv). The dependents truth is measured by the same checks.csv, and usable reach by finding the credentials/URLs the team placed in config. evaluation.md claims truth "is never read from lab/*.csv" (L85) — true mechanically, but both were authored from the same design intent; near-perfect B4 F1 (0.97–1.00) is close to tautological.
- **Free credit from empty sets**: "An empty prediction has precision 1, and an empty truth set has recall 1" — [eval_kg/metrics.py L213-219](eval_kg/metrics.py). Result: B0 (no blast radius) scores F1 0.471 on usable and 0.412 on dependents (17-host) purely because 8/17 and 7/17 hosts have empty truth — [data/reports/eval_blast_radius.md](data/reports/eval_blast_radius.md). Per-asset macro-averaging gives hosts with ∅ the same weight as hosts with real blast radius.
- **Network truth contradicts B4**: on TCP reachability B4 recall is 0.088 and B2 is perfect; docs explain this as expected ("The network set alone would favour B2, because this lab's firewall works per zone") — [docs/evaluation.md L93-96](docs/evaluation.md). Choosing the truth set that favours the proposed method after seeing the alternatives is a researcher-degrees-of-freedom risk unless the "usable/dependents are primary" decision is justified a priori.
- **Zone predicate never exercised**: all 12 CONNECTS_TO edges survive π (my computation above), so B3 vs B4 tests only direction, and nothing tests the zone constraint of Eqs. 5–6.
- **Mode-truth mapping fixes direction by construction**: compromise is scored only against usable (outbound) and disruption only against dependents (inbound) — [eval_kg/run.py L359, L409](eval_kg/run.py). The undirected B3 is guaranteed to lose precision against a directional truth; this tests "direction matters" only if the truth itself was not designed directionally.
- **What feeds EVS is not what Part B validates**: EVS uses `propagation` (unbounded, outbound only, model.py L65-71); Part B validates `blast_radius` k=1 (L60-62). `distances_for_p` makes B4 = B5 for the downstream row (variants.py L322). The downstream row is flat 1.000 for all variants (one positive) — [data/reports/eval_blast_radius.md](data/reports/eval_blast_radius.md).
- **Propagation effect is tiny**: P(u) ≤ 0.1211 → uplift ≤ 6.05 % (Jump); 8/17 assets have P = 0 (my computation). The 1/(|V_A|−1) normaliser means P shrinks as the network grows (8-host Nginx example 0.125 in [docs/scoring.md L68-69](docs/scoring.md) vs 0.0547 now).
- **EVS ceiling**: "the lab's only alertable CVEs and its only repeatable exploit are all CVSS 9.8 (ceiling), so an A2 EVS-beats-CVSS result is not reachable here" — [data/reports/eval_sensitivity.md](data/reports/eval_sensitivity.md); min(10, …) saturates at the top where triage decisions matter.
- **Bootstrap on n = 9 with one positive**: resamples without the positive return None and are skipped (metrics.py L235-237), so CIs are conditioned on the positive being present — degenerate [0, 0] intervals are reported as if informative.
- **NDCG@10 on ≤ 9 items** is essentially full-list NDCG; P@10 = 0.100 is capped by the single positive.
- **A2 technique-inferred CVEs**: A2 turns on `technique_matches=True` so ATT&CK-technique-inferred CVEs become "instances" (e.g. SQLi rule 31164 → T1055 → Apache CVE-2024-38476) — [docs/evaluation.md L167-183](docs/evaluation.md). These inferred instances are mostly grade 0/1 noise (S04–S07), and E = H is set for them (run.py L69 `alerted: True`), which evaluation.md says the scoring CLI deliberately avoids (L170-171).
- **CR/IR/AR assigned by the same team**, partly "drafted from the role, not yet confirmed by the team" for the 9 new hosts — [lab/assets.csv L1-5](lab/assets.csv). Sensitivity "direction check" then measures that EVS follows CR/IR/AR, which is true by construction (tautological).
- **Sensitivity is not validation**, as the code says: "It does not show the reordering is correct" — [eval_kg/run.py L299-305](eval_kg/run.py).
- **Missing baselines/ablations**: no random baseline; no "CVSS+EPSS" or "CVSS Environmental by hand" (manual analyst) baseline; no leave-one-out ablation (each component removed from full EVS) — only cumulative additions, so order effects are untested; no β/γ sensitivity against labels (only `score_kg sensitivity` on ranking change, [docs/scoring.md L84-85](docs/scoring.md)); no evaluation of the risk-level classification (Eq. 18) although the paper is titled "classification"; no evaluation of the LLM threat report validation step; no comparison to a CVSS v4.0 environmental score.
- PLAN.md §6 originally proposed tier (C) "Agreement with experts (weighted κ)" and "Spearman correlation with the analyst labels" — [docs/PLAN.md L22, L122-129](docs/PLAN.md); this tier was never built.
- Threats to validity listed: small lab (17 hosts, 5 zones), labels from same team, lab-specific truth, usable reach lower bound, Wazuh is scanner view — [docs/evaluation.md L104-114](docs/evaluation.md).

### Inferences
- The evaluation asks a question the lab cannot answer: "does EVS rank *exploitable* CVEs higher than CVSS?" Exploitability in a container lab is dominated by whether the vulnerable feature is configured/reachable, which none of the score's inputs (CR/IR/AR, zone MAV, P) model — so even with more labels, the ladder rungs L1 and L4 have no causal reason to predict "exploited". The EVS's actual claim is about *impact/priority given context*, so labels should measure consequence (what an attacker gained, what broke, what an analyst would prioritise), not exploit success alone.
- A stronger and non-circular framing for Part A would compare score rankings against *measured consequence* (e.g. grade from scenario outcome × measured blast of the compromised host) or against independent expert/SOC rankings (pairwise judgements, weighted κ / Kendall), and use per-asset "same CVE, different host" contrasts (e.g. CVE-2024-6387 on Admin-PC 7.3 vs Dep-PC 5.4) as the core demonstration.
- For Part B, the truth should be measured with a procedure not derived from the same design (e.g. actual pentest pivots from S01/S08/S10/S12, or an independent person setting service configs/credentials, or nmap/traffic-flow capture of real flows), and the zone predicate should be exercised by at least one CONNECTS_TO edge that crosses a denied zone pair.
- Report micro-averaged (pooled TP/FP/FN) metrics and exclude or separately report hosts with empty truth to remove the B0 free credit.

### Gaps
- I did not verify whether tests cover tie handling or the empty-set convention beyond the passing offline tests.
- No inter-rater or second-team labelling exists to quantify label bias.
